# НормаКонтроль ОПО — Windows 1.0 RC3

Портативное приложение для Windows 10 22H2 / Windows 11 x64. **Работает только с USB-флешкой-ключом**, на которой издатель записал файл лицензии NormaControl.lic. Распакуйте архив целиком в доступную для записи папку, вставьте флешку-ключ и запустите **NormaControl.exe**. Python и библиотеки PDF входят в комплект; отдельная установка Python не нужна. Права администратора не требуются. При первом запуске приложение индексирует документы: дождитесь появления вкладок.

## Лицензия: флешка-ключ

- Без флешки-ключа программа не запускается и показывает причину (нет USB-накопителя, нет файла лицензии, лицензия для другой флешки, истёк срок, файл изменён).
- Флешка должна оставаться подключённой: программа проверяет её каждые 15 секунд. Если ключ извлечь, появится предупреждение; если не вернуть его в течение 60 секунд, программа закроется. Внесённые данные к этому моменту уже сохранены.
- Лицензия подписана издателем и привязана к конкретной флешке: скопировать файл на другую флешку или изменить владельца/срок нельзя. Не форматируйте флешку-ключ — лицензия будет удалена, её придётся выдать заново.
- Владелец, номер и срок лицензии видны в строке состояния окна; Diagnostics_Windows.cmd показывает состояние ключа (серийные номера в отчёты не записываются).
- Лицензии выдаёт издатель отдельным комплектом с закрытым ключом; он не входит в этот архив.

Модули программы поставляются в скомпилированном виде (.pyc); при запуске проверяется, что файлы программы не изменены и не добавлены посторонние модули. Исходный код хранится у разработчика.

## Что нового в RC3

- Защита лицензией на USB-флешке (см. выше) и проверка целостности файлов программы.
- Один архив вместо двух частей (неиспользуемые части встроенного Python исключены; pip для инструментов обучения загружается при их установке).

## Что нового в RC2

- Из нормативной базы удалены служебные надписи справочных систем: плашки «Документ предоставлен…», «Дата сохранения», колонтитулы с адресом сайта, логотипы, редакционные примечания системы, ссылки на её сайт и сведения о программе выгрузки; из копии №534 — строки и логотип сайта-распространителя. Текст норм и отметки «(в ред. …)» сохранены. База RC1 обновляется автоматически при первом запуске: ссылки [К…-Ф…], отметки проверки и решения сохраняются. Подробно: ND_IMPORT_RU.md.
- Исправления для Windows: включён режим UTF-8 (в RC1 он фактически не работал), окно подстраивается под экран и масштаб 125–200 %, при первой индексации окно не «зависает», внешние программы (Tesseract, nvidia-smi, Ollama) запускаются без мигающих консолей, фото с телефона в PDF поворачиваются правильно, резервная копия пишется атомарно и проверяется, .cmd-файлы в формате Windows (CRLF).
- Приёмочная проверка одним файлом: **Acceptance_Windows.cmd** (на временной базе, ваши данные не меняются).
- Обучение: установка PyTorch с CUDA, рекомендация размера базовой модели по свободной видеопамяти, оценка ответов отдельно от loss (evaluate_lora.py), быстрая проверка конвейера (tools\lora_pipeline_check.py).

## Проверка на вашем компьютере (порядок)

0. Вставьте флешку-ключ. Без неё работает только Diagnostics_Windows.cmd (он покажет, найден ли ключ).
1. **Diagnostics_Windows.cmd** — создаёт Windows_self_test.json (версии, UTF-8, FTS5, окно Tk, GPU и память без идентификаторов устройства).
2. **Acceptance_Windows.cmd** — полный сценарий на временной базе: индексация НД, поиск, ситуация с фото → источники → решение → PDF, резервная копия с восстановлением, повторное открытие, окно и масштаб, OCR. Отчёт: папка acceptance (Acceptance_report_*.json и .txt, копия PDF и снимок окна).
3. После установки Ollama и модели (раздел ниже) повторите: `Acceptance_Windows.cmd --model qwen2.5:14b`. Для своего фото/документа: `--photo "C:\путь\фото.jpg" --document "C:\путь\акт.pdf"`. В отчёт попадут скорость (токенов/с), доля модели в видеопамяти, использование GPU, проверка ссылок [К-Ф] и снимок сетевых соединений программы и Ollama.
4. Пришлите разработчику файлы из папки acceptance и Windows_self_test.json. Серийных номеров, имени компьютера и пользователя в них нет; снимок окна и PDF содержат только тестовые данные и реестр ОПО — проверьте их перед отправкой.

## Ваш компьютер

Профиль по фотографиям: Windows 10 Pro 22H2 x64, Intel i7-10700, 64 ГБ RAM, NVIDIA RTX A5000. Фактическая свободная видеопамять и работа CUDA на вашем ПК ещё не проверены. Запустите Diagnostics_Windows.cmd: отчёт Windows_self_test.json содержит локальную диагностику без идентификаторов устройства. Для модели и пакетов обучения понадобится дополнительное место на диске.

## Документы

В комплекте 19 DOCX из предоставленного архива НД, очищенных от служебных надписей справочной системы. №517 исключён. Источники автоматически разрешены для поиска как предоставленные пользователем, но НЕ отмечены юридически проверенными. Редакции взяты из самих файлов: их действительность на дату эксплуатации требует сверки. Также сохранены прежняя пользовательская копия №534 и два текста ТР ТС. Всего 22 полных текста и 46 карточек каталога; карточка не заменяет текст документа. Старые непроверенные источники не включаются в поиск автоматически.

Это корпус предоставленных материалов, а не все возможные документы для любого нефтегазового предприятия. Применимость зависит от оборудования и работ. Вкладка «Проверенные требования» предназначена для требований, проверенных специалистом и связанных с настоящим источником/фрагментом. Демонстрационные правила исходного веб-прототипа сюда не перенесены.

## Первый запуск локального ИИ

1. Установите Ollama для Windows с https://ollama.com/download/windows .
2. Запустите Install_Local_Model.cmd: он загрузит qwen2.5:14b (около 9 ГБ, нужен интернет).
3. Завершите ранее запущенный сервер Ollama, затем запустите Start_Ollama_Local.cmd. Оставьте окно сервера открытым.
4. В приложении откройте «Локальные агенты», обновите список моделей, выберите qwen2.5:14b, сохраните настройки и задайте вопрос. Адрес: http://127.0.0.1:11434.

После установки весов документы и запросы обрабатываются локально. Облачные модели и внешние адреса сервера запрещены программой. Веса Ollama не включены в архив. Реальная генерация и скорость на RTX A5000 ещё не измерены; при недостатке ресурсов можно отдельно загрузить qwen2.5:7b. Текстовая модель не анализирует фотографии автоматически.

## Обучение

Сначала используйте базу знаний: добавление документов не требует обучения весов. Для LoRA нужны проверенные пары вопрос/ответ, раздельные train/validation и локальная папка базовой Hugging Face-модели. Install_Training_Tools.cmd устанавливает PyTorch с CUDA и остальные пакеты (3–4 ГБ). Затем выполните `runtime\python.exe -I -X utf8 tools\lora_pipeline_check.py`: за 1–3 минуты проверяется весь конвейер на крошечной случайной модели и видимость CUDA. Для RTX A5000 (24 ГБ) реалистична база 7B (например, Qwen2.5-7B-Instruct в формате Hugging Face); 14B без 4-битной загрузки не помещается. На время обучения выгрузите модель Ollama (`ollama stop qwen2.5:14b`). После обучения сравните ответы: `runtime\python.exe -I -X utf8 evaluate_lora.py ...` (см. LOCAL_AI_RU.md) и заполните лист answer_review.csv. Реальное обучение и качество обученной модели в этой сборке не проверены. Сами модельные веса и CUDA-библиотеки не входят в архив или резервную копию.

## Данные и обновления

Новая база: %LOCALAPPDATA%\NormaControlOPO. Если обнаружена существующая база PromControlStage1, программа продолжает использовать её. Перед обновлением создайте резервную копию в приложении. Обновляйте папку программы целиком, оставляя пользовательские данные. Переменная PROMCONTROL_DATA_DIR задаёт иной путь для тестирования. Ошибки запуска сохраняются в %LOCALAPPDATA%\NormaControlOPO\logs.

Итоговый риск и решение фиксирует специалист. Подбор источников или ответ ИИ сам по себе не подтверждает нарушение, соответствие либо готовность ОПО к эксплуатации.
