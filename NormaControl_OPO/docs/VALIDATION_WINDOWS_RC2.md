Документ разделяет то, что проверено фактически, и то, что требует проверки на компьютере пользователя. «Под Wine» означает: встроенный Windows-runtime комплекта (Python 3.13.16 x64 с официального установщика, без подмены Linux-библиотеками) запущен в Wine 9.0 под Linux. Это ближе к Windows, чем запуск на Linux-Python, но **не равно проверке на настоящей Windows 10**.

| Ошибка RC1 | Где обнаружена | Исправление RC2 |
|---|---|---|

| .cmd-файлы с окончаниями строк LF (у cmd.exe ненадёжны метки/goto) | Анализ файлов | Все .cmd в CRLF |
| Окно 1380×850 больше экрана 1366×768 и Full HD при 125–150 %: обрезаны правый край, строка статуса, нижние списки | Скриншоты Xvfb 1366×768 | Размер по рабочей области, DPI-aware (как IDLE), разворот на малом экране, статус закреплён, перенос длинных подписей по ширине окна |
| При первой индексации окно не обрабатывает события (Windows помечает «Не отвечает») | Анализ кода | Прогресс «N из 46» с обновлением окна; закрытие во время подготовки заблокировано |

| Сообщение при отсутствии Tesseract не называло язык; тест падал на Windows без Tesseract | Win64-runtime под Wine | Сообщение называет rus/eng и путь установки |

## 4. Не выполнено (и почему)

- Запуск на настоящей Windows 10 Pro 22H2 с RTX A5000: компьютер пользователя недоступен из этой среды.
- Ollama, модели qwen2.5:14b/7b, генерация, скорость, VRAM, отсутствие внешней передачи на практике: сетевые правила среды блокируют ollama.com, registry.ollama.ai, huggingface.co и download.pytorch.org (ответ 403). Логика локальности (только loopback, запрет облачных моделей) по-прежнему проверяется тестами с локальным HTTP-сервером.
- LoRA на реальных весах и GPU, импорт обученной модели в Ollama.
- Русский OCR на Windows.
- Юридическая актуальность редакций и применимость норм к конкретным работам.

## 5. Обучение на Win64-runtime под Wine

- `runtime\python.exe -I -X utf8 -m ensurepip` во встроенном runtime: pip 26.2.1 установлен.
- `pip install` колёс cp313 win_amd64 с PyPI во встроенный runtime: torch 2.14.1 (CPU-сборка PyPI), transformers 4.57.6, peft 0.21.1, safetensors 0.8.0, tokenizers 0.22.2 — установлены.
- Запуск torch под Wine 9.0 невозможен: в Wine не реализована функция ucrtbase.crealf, которую вызывает torch для Windows. Это ограничение Wine, а не Windows; обучение на Win64-runtime проверяется только на настоящей Windows (`tools\lora_pipeline_check.py`).
- CUDA-сборки PyTorch (download.pytorch.org) в этой среде недоступны (403); установщик пробует cu130 → cu128 → cu126 и печатает, видна ли CUDA. Логика попыток проверена в `wine cmd` на заглушках вместо pip (первоначальный вариант с `goto` внутри `for` под Wine продолжал цикл — заменён последовательными попытками).
- Diagnostics_Windows.cmd выполнен через `wine cmd` из распакованного архива: Windows_self_test.json создан.

## 7. Что сделать на целевой машине

1. Diagnostics_Windows.cmd → Windows_self_test.json (ожидается utf8_mode=true, fts5=ok, tk_window=ok, GPU RTX A5000 с драйвером).
2. Acceptance_Windows.cmd → отчёт acceptance\Acceptance_report_*.json/.txt.
3. Установка Ollama → Install_Local_Model.cmd → Start_Ollama_Local.cmd → `Acceptance_Windows.cmd --model qwen2.5:14b --photo "…" --document "…"`. Критерии: model_in_vram_percent = 100, приемлемые tokens_per_second, refs_cited_not_provided пуст, non_loopback_connections пуст.
4. Ручной сценарий в программе: ситуация с вашим фото → «Подобрать источники» → открыть оригинал → решение специалиста → PDF; перезапуск; «Резервная копия».
5. Install_Training_Tools.cmd → `runtime\python.exe -I -X utf8 tools\lora_pipeline_check.py` (cuda=true) → база Qwen2.5-7B-Instruct (Hugging Face) → проверенные специалистом примеры → обучение (Ollama выгружен) → evaluate_lora.py → answer_review.csv.
6. Вернуть разработчику: Windows_self_test.json, папку acceptance, pipeline_check.json, answer_eval.json, журналы %LOCALAPPDATA%\NormaControlOPO\logs (если есть).

RC2 — кандидат сборки. Промышленная готовность и правовая актуальность этим отчётом не подтверждаются.
