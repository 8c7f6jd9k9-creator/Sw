# Проверка Windows 1.0 RC3 (лицензия на USB-флешке) — 01.10.2026

RC3 = RC2 + защита лицензией на USB-флешке + проверка целостности + один архив. Остальные результаты и ограничения — docs/VALIDATION_WINDOWS_RC2.md.

## Как устроено

- Файл `NormaControl.lic` в корне флешки: JSON с данными лицензии (номер, владелец, даты выдачи и окончания, продукт и основная версия, накопитель) и подписью Ed25519 издателя. В программе — только открытый ключ (usb_license.PUBLIC_KEYS); закрытый ключ находится в отдельном комплекте издателя.
- Привязка: шина USB, серийный номер USB-устройства (IOCTL_STORAGE_QUERY_PROPERTY) и серийный номер тома (GetVolumeInformationW). Изменение любого поля лицензии ломает подпись; копия на другую флешку не проходит сверку номеров.
- Проверка при запуске (до создания окна и до открытия базы) и каждые 15 с; при отсутствии ключа — предупреждение и закрытие через 60 с.
- Ed25519 реализован на чистом Python (nc_ed25519.py) по RFC 8032, без сторонних библиотек.
- Клиентская сборка: 22 модуля программы в байт-коде Python 3.13 без исходников; entry.pyc содержит SHA-256 остальных модулей и список допустимых файлов. Изменённый модуль или посторонний .py/.pyc/.pyd/.dll в папке программы — отказ запуска (журнал integrity_*.txt). Папка программы добавляется в конец пути импорта, поэтому не может перекрыть стандартные модули.

## Проверено

- Ed25519: тестовые векторы RFC 8032 (3), сверка с библиотекой cryptography на 200 случайных ключах и сообщениях (подписи побайтно совпадают, изменённые подписи отвергаются). Проверка подписи ~4 мс.
- Unit-тесты (Linux, Python 3.12): 91 OK, 1 пропуск. Новые 14 тестов: действительная лицензия; копия на другую флешку, другой том, не USB; изменённый файл, чужой ключ, подпись не тем ключом, другая версия; даты; отсутствие/повреждение файла, несколько флешек; шестнадцатеричная запись серийного номера; сбой опроса дисков; отказ App до создания окна; код выхода 3 и журнал без создания базы; контроль целостности; извлечение и возврат ключа во время работы.
- Встроенный Win64-runtime под Wine 9.0, собранный архив после распаковки:
  - Реальные вызовы Windows API: GetLogicalDrives, GetDriveTypeW, CreateFileW, DeviceIoControl(IOCTL_STORAGE_QUERY_PROPERTY) выполнились без ошибок (для C: получен дескриптор шины SCSI → правильно не принят как USB). USB-устройств Wine не предоставляет.
  - NormaControl.exe без ключа: сообщение о лицензии (снимок проверен), журнал license_*.txt, папка данных не создаётся.
  - С ключом (флешка эмулирована папкой, файл лицензии настоящий — выдан рабочим ключом через комплект издателя): приёмка 11 OK / 0 FAIL / 2 SKIP (OCR, Ollama).
  - Извлечение ключа в работающем окне: предупреждение с отсчётом; возврат в течение 60 с — работа продолжается; без возврата окно закрывается, затем показывается сообщение; база после закрытия: integrity_check ok.
  - Подмена: usb_license.py, hashlib.py, ui_scale.py рядом с программой и изменённый app.pyc — во всех случаях отказ запуска с журналом integrity_*.txt.
  - Комплект издателя: .cmd находит runtime программы; выдача, проверка, защита от перезаписи без --force, перезапись с --force, журнал issued_licenses.csv.

## Один архив

Поставка — один архив NormaControl_OPO_Windows_1.0_RC3.zip (29.2 МБ; ограничение передачи файла — 30 МБ): READ_ME_FIRST_RU.txt, папка программы NormaControl_OPO и папка комплекта издателя NormaControl_License_Kit_PRIVATE.

Чтобы уложиться в один файл без потери функций, из встроенного runtime исключены 928 файлов, которые программа не использует: IDLE, venv, справка pydoc, NEWS.txt, демо и картинки Tk, часовые пояса Tcl, файлы для сборки расширений, кодеки AVIF/WebP у Pillow (изображения для OCR передаются Tesseract напрямую, вложения ситуаций — JPEG/PNG/TIFF), образцы шрифтов ReportLab (отчёты используют свой DejaVuSans.ttf; трассировка открытия файлов при построении PDF подтвердила, что каталог шрифтов ReportLab не читается) и колесо pip. Остальные файлы runtime совпадают по SHA-256 с поставкой RC1. Перечень — docs/RUNTIME_PROVENANCE.json, tools/build_release.py (LEAN_REMOVE).

Единственное отличие в поведении: pip для инструментов обучения загружается при их установке (tools/bootstrap_pip.py: только pypi.org/files.pythonhosted.org, сверка SHA-256; при наличии колеса в комплекте — ensurepip без интернета). Установка PyTorch требует интернета в любом случае. Оба пути проверены (Windows-runtime под Wine и Linux); запуск pip «как python -m pip» нужен, иначе pip на Windows отказывается устанавливать сам себя.

Проверено на облегчённом runtime под Wine: 91 unittest OK (3 пропуска), self-test, приёмка 11 OK / 0 FAIL / 2 SKIP, PDF с кириллицей и фото, отказ без ключа, выдача лицензии комплектом из папки NormaControl_License_Kit_PRIVATE и приём её программой.

## Не проверено

- Настоящая USB-флешка на настоящей Windows: получение серийного номера через IOCTL на реальном устройстве. Проверьте Check_USB_Key.cmd (комплект издателя) и Diagnostics_Windows.cmd на целевом ПК. Если у флешки нет серийного номера USB, инструмент откажет в выдаче — нужна другая флешка.
- Устойчивость к целенаправленному взлому специалистом (правка байт-кода, клонирование серийного номера на уровне прошивки флешки). Это программная защита; для строгой защиты нужен аппаратный ключ с защищённым чипом.
